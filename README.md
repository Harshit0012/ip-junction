# IPJunction website

Marketing site for IPJunction Inc., built with Astro as a static site and deployed to GitHub Pages.

## Run locally

```sh
npm install
npm run dev        # http://localhost:4321/ip-junction/
npm run build      # static output in dist/
npm test           # Playwright: every route, axe (WCAG 2.2 AA), consent, form, mobile nav
```

## Configuration

All settings are optional build-time variables. Set them as GitHub repository **variables** (Settings → Secrets and variables → Actions → Variables). Locally, copy `.env.example` to `.env`.

| Variable | Effect when empty | Effect when set |
| --- | --- | --- |
| `PUBLIC_CAL_LINK` | Contact page shows "Email to book" | Inline Cal.com scheduler, loaded on click (e.g. `deepak-kataria/30min`) |
| `PUBLIC_WEB3FORMS_KEY` | Form is shown disabled with an email fallback | Form posts to Web3Forms. The key is public by design. |
| `PUBLIC_UMAMI_ID` | No analytics, no consent banner | Consent banner appears; Umami loads only after Accept |
| `PUBLIC_INDEXABLE` | Every page is `noindex` and robots.txt blocks crawlers (prototype) | Set to `true` at launch |
| `SITE_URL`, `BASE_PATH` | Serves at `https://harshit0012.github.io/ip-junction/` | Custom domain: `https://www.ip-junction.com` and `/` |

When moving to a custom domain, also change `public_folder` in `public/admin/config.yml` to `/uploads`.

## Editing content (no code)

Insights, Updates (changelog) and Careers are Markdown files in `src/content/`, edited through Sveltia CMS at `/admin/`.

- **Prototype sign-in:** create a fine-grained GitHub token for this repo with *Contents: read and write*, then use "Sign in with Token".
  Give the token a short expiry (30 days or less), limit it to this repository, and grant **only** Contents. Never grant Workflows or Administration: anyone holding the token can publish to the live site.
- **Production sign-in:** deploy [sveltia-cms-auth](https://github.com/sveltia/sveltia-cms-auth) to Cloudflare Workers (free) and set `base_url` in `public/admin/config.yml`. Editors then sign in with their normal GitHub account.

Saving in the CMS commits to `main`, which runs the tests and redeploys the site within a few minutes.

## Security headers

GitHub Pages cannot send custom HTTP headers. Each page carries a Content Security Policy in a `<meta>` tag, generated by Astro with script and style hashes, plus a referrer policy. `public/_headers` holds the full header set (HSTS, nosniff, frame denial, Permissions-Policy) for Cloudflare Pages or Netlify, which read that file automatically.

Known gap on GitHub Pages: `frame-ancestors` and `X-Frame-Options` cannot be set through a meta tag, so clickjacking protection only applies once the site moves to a host that reads `_headers`. The site holds no logged-in state, so the exposure is low.

## Before launch

- Restrict the Web3Forms access key to the production domain in the Web3Forms dashboard.
- Open the scheduler with the real `PUBLIC_CAL_LINK` and check the browser console for CSP errors.
- Protect `main` and require the `test` check (decide how CMS commits should flow first).
- Replace the redrawn logo and the deck-derived founder photo with original files.
- Set `PUBLIC_INDEXABLE=true`.
